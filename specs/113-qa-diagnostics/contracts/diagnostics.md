# S113 interface contracts

## Maintainer evaluation

The coordinator exposes validated timing policy to the PowerShell wrapper. Capture/resume use the same resolved budget. Invalid or mismatched original input fails before mutation. Execution cancellation has an independent bounded shutdown/report reserve; an outer forced stop preserves captured output and names exact original inputs and recovery route.

New report diagnostics are additive entries inside existing hash-bound state artifacts; the strict v1 report envelope remains unchanged. Diagnostics are bounded by phase count/request count and existing evidence limits. They may contain safe method, route template, elapsed duration and error category, never headers, bodies, tokens or arbitrary secret-bearing URLs. Retained report schema/hash validation stays strict. Canonical JSON and the fixed seven-section report distinguish command success from later inspection failure. Incomplete snapshots remain unsuccessful for full assertions.

## Delivery evidence

NotificationDelivery adds optional diagnostic. last_error remains optional and means actual failure information; complete SMTP acceptance has diagnostic and no last_error. Partial rejection/retry/uncertain submission retains actionable errors and recipient-level evidence. This is a semantic bug correction plus an additive field, not removal of the existing key. Old stored SMTP success evidence is preserved in diagnostic by migration24. Webhook history is unchanged. Server acceptance is not final inbox receipt.

## Payload prerequisites

Explicit invalid SQLite selection refuses fallback; implicit unusable candidates may fall through while retaining bounded rejection context. Version tokens must be numeric and satisfy the existing minimum. Runtime crash, timeout, malformed/old version, missing executable and ordinary command failure remain distinct. Existing hidden containment and exact six-writer assertions remain required.
