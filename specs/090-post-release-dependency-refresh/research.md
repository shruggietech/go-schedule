# Research: Post-release dependency refresh

## Source Inventory

| Pull request | Requested direct updates | Current-main consideration |
| --- | --- | --- |
| #240 | x/sys 0.48.0 | Overlaps #241 and requires Go 1.26. |
| #241 | go-sdk 1.8.0, x/crypto 0.57.0, x/time 0.16.0 | Resolver also selects current x/mod, x/net, x/sync, x/sys, x/text, and x/tools companions; selected x modules require Go 1.26. |
| #242 | React and React DOM 19.3.0, matching types, Node types 26.5.1, Vite 8.3.0 | Lockfile adds the matching scheduler and Vite companion revisions while retaining Node 26. |

## Decisions

### Adopt Go 1.26 in both modules

The selected x/crypto, x/sys, and x/time releases declare Go 1.26. Leaving either module at 1.25 would rely on implicit toolchain switching while publishing a contradictory supported baseline. Both module declarations and human guidance advance together. Workflows already use `go-version-file`, so no hard-coded workflow version needs duplication.

### Consolidate overlapping Go proposals

#241 already resolves x/sys 0.48.0, so applying #240 separately would duplicate the same graph transition and retain stale-branch CI noise. S090 uses one root resolution, then tidies the desktop graph against its local root replacement.

### Retain Node 26

The frontend proposals remain compatible with the existing Node 26 engine and workflow baseline. No Node-major or TypeScript change is justified.

### Preserve native resolver authority

Go checksums and npm lock entries are generated by their package managers. Source diffs are inputs for version selection and traceability, not files to transplant from stale automated branches.

### Close source pull requests after replacement publication

Once the official S090 PR exists, the automated proposals no longer have independent delivery value. Each source PR receives a link to the replacement before closure. The tracking issue remains open until S090 merges.
