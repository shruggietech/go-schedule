# S123 diagnostic data model

## Candidate

Role (historical/current), base revision, dirty flag, source content digest, prepared binary digests, test executable hash, wrapper/adapter identities and available collector capability. Historical dirty bytes never inherit a clean revision claim.

## Condition

Track, candidate, controller identity, interpreter or packaged-store selection, case allowance, collection selection, repetition, original campaign deadline, start/end, native result, expected result, independent protocol/inspection/collection/cleanup outcomes and log hashes.

## Disposition

Original symptom, hypothesis, supporting/contradictory observations, matching recurrence identity or explicit absence, separate defect/fix reference, remaining uncertainty and issue outcome.

## Transitions

Prepared -> identity/compatibility checked -> attempted -> completed/failed/unavailable/interrupted -> cleanup recorded. Failed conditions are never overwritten by later successful attempts. Existing campaign sidecar supplements the canonical QA schema.
