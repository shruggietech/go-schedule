## Relationships

- Each source update maps to exactly one final disposition in the replacement pull request.
- The consolidated baseline owns all manifest and integrity-file changes produced by the selected versions.
- A compatibility adjustment must identify the source update that requires it.
- Verification evidence identifies the exact branch commit and gate that produced it.

## Validation Rules

- Direct versions remain exact because the existing frontend manifest uses exact pins.
- Root and desktop module files must be tidy independently while the desktop module retains its local root replacement.
- `package-lock.json` must be generated by the declared npm toolchain and accepted by `npm ci` with no peer or engine bypass.
- No application database schema version changes.
- No source pull request transitions to closed before the replacement merges.
